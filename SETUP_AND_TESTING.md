# Настройка и проверка: клининговый шаблон + приложение продаж

## Что вы получаете

Один шаблон сайта для клининговых компаний, приложение продаж `/admin` и неограниченную кодом базу карточек в Redis (практический объём зависит от тарифа, времени функций и размера базы). При сохранении карточки её публичный пример сразу доступен по `/p/<случайный-id>`. Отдельные проекты или деплои для каждого примера не нужны. Все примеры используют один шаблон; его обновление меняет их все.

Другие отрасли и конструктор шаблонов в эту версию не включены.

### Два разных режима

| Режим | Настройки | Что происходит с заявкой |
| --- | --- | --- |
| Ваш демонстрационный проект / приложение продаж | `config.js`: `site.demo: true`, заполнен `ADMIN_PASSWORD`, подключён Redis | Главная и все `/p/*` работают как тест. Форма проверяется, показывает расчёт и тестовый номер. Имя и телефон не сохраняются и не отправляются в Telegram. Для примера учитывается только количество тестов формы. |
| Настоящий сайт клиента | Отдельный проект/копия, реальные данные в `config.js`, `site.demo: false`, **нет** `ADMIN_PASSWORD`, собственные Telegram и Redis | Реальная заявка уходит менеджеру клиента, сохраняется в Redis и управляется из Telegram. |

**Важно:** персональная ссылка из CRM — концепт, а не официальный сайт компании. Любой, у кого есть ссылка, может видеть опубликованные название, контакты, адрес, часы, цвет и цены. Заметки, источники, статусы и история CRM не публикуются. Добавляйте только разрешённые для публикации сведения. Не храните в карточке лишние персональные данные.

## 1. Первый запуск вашего приложения продаж на Vercel

1. После принятия изменений в GitHub откройте Vercel → Add New → Project и импортируйте репозиторий.
2. Framework Preset: **Other**. Build Command: пусто. Output Directory: `.`. Node.js: актуальная поддерживаемая версия 22 или новее. Если Vercel автоматически выставил команду сборки, отключите её: сборка проекту не нужна.
3. Vercel → Storage / Marketplace → подключите Upstash Redis. Привяжите интеграцию к этому проекту и Production (и к Preview, если хотите проверять ветки).
4. В Settings → Environment Variables должны появиться **оба** значения: `KV_REST_API_URL` и `KV_REST_API_TOKEN`. Также поддерживаются альтернативные имена `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN`.
5. Добавьте `ADMIN_PASSWORD`: уникальный случайный пароль, желательно от 20 символов. Сохраните его в менеджере паролей. Никогда не добавляйте реальный пароль в GitHub или `config.js`.
6. Оставьте `site.demo: true` в `config.js`. Telegram для демонстраций не требуется.
7. Deploy / Redeploy. Скопируйте HTTPS-адрес проекта.
8. Откройте `<адрес>/admin`, введите пароль. Сессия действует до 8 часов и хранится в HttpOnly-cookie, а не в localStorage. После изменения пароля старые сессии перестают проходить проверку.
9. В Vercel убедитесь, что публичные ссылки **не закрыты Deployment Protection / Vercel Authentication**. Иначе компании будут видеть вход Vercel вместо примера. Не отключайте защиту для посторонних проектов; проверяйте именно нужный Production-домен.

Для приложения продаж хватит одного Vercel-проекта и одного Redis. Для реальных клиентских сайтов используйте отдельные проекты и отдельные базы. Не подключайте тестовое окружение к базе с реальными заявками.

После любого изменения переменных окружения нужен **Redeploy**. Существующий деплой не получает новые значения автоматически.

## 2. Ваш ежедневный рабочий процесс

1. `/admin` → **Новый лид**.
2. Вставьте текст карточки из 2ГИС, Яндекс Карт или сайта в «Быстрое заполнение». Это локальное распознавание текста, а не парсер сайтов и не обращение к сервисам карт. Оно не гарантирует идеальный результат: проверьте поля.
3. Заполните название, город, телефон, адрес, часы, ссылки на источники. Оставляйте заметки только в закрытом поле «Заметки».
4. Укажите контакты для сообщения:
   - **WhatsApp:** номер в международном формате; если поле пустое, используется телефон компании.
   - **Telegram:** `@username`, HTTPS-ссылка или номер. Возможность найти человека по номеру зависит от настроек Telegram. Имя пользователя или проверенная ссылка надёжнее.
   - **MAX:** **полная ссылка на чат**, скопированная из приложения MAX, на домене `max.ru` или `max.im`. Один номер не преобразуется в гарантированно рабочую ссылку.
5. В «Сайт-пример» выберите цвет, подпись логотипа/флакона и тарифы. Дополнительные услуги берутся из общего `config.js`.
6. **Сохранить и обновить сайт**. В карточке появляются публичная ссылка и встроенный предпросмотр. Нового деплоя ждать не надо.
7. **Открыть ↗** использует `?own=1`: ваши проверки не увеличивают счётчик. Кнопка «Копировать» даёт обычную публичную ссылку для клиента, без `own=1`.
8. Выберите шаблон оффера и отредактируйте текст под компанию. Ваш ручной текст сохраняется в текущем редакторе при сохранении карточки, но это не отдельное серверное хранилище черновиков.
9. Нажмите кнопку нужного мессенджера:
   - WhatsApp открывает чат с текстом в ссылке; **отправку нажимаете вы**.
   - Telegram и MAX открывают чат; текст копируется в буфер, его нужно вставить и отправить.
   - «Копировать» только копирует текст.
10. После действительной отправки нажмите **«Подтвердить, что отправлено»**. Открытие чата или копирование не переводят компанию в «Оффер отправлен». История отличает подготовку от подтверждённой вами отправки. Это не подтверждение доставки или прочтения от мессенджера.
11. Меняйте статусы: Новый → Оффер отправлен → Ответил → Есть интерес → Клиент / Отказ.

Текстовые шаблоны сохраняются в браузере (localStorage), а карточки — в Redis. На другом устройстве карточки доступны после входа, но ваши локальные шаблоны не синхронизируются.

**Не используйте приложение для массовой нежелательной рассылки.** Проверяйте контакты, уместность предложения и правила мессенджеров, уважайте отказы. Приложение не отправляет сообщения от вашего аккаунта через API и не обходит ограничения площадок.

### Большая база

Карточки загружаются порциями по 100; кнопка «Загрузить ещё 100» добавляет следующую порцию. Поиск и фильтр статуса выполняются на сервере по всей базе, а не только среди загруженных карточек. Сводка сверху относится к загруженным карточкам. CSV-экспорт проходит все страницы текущего поиска/статуса, а не только первую сотню. Большой экспорт может занять время; не меняйте базу параллельно с ним. Формульные значения экранируются для Excel. CSV не содержит полной истории действий и не заменяет резервную копию Redis.

### Что означают просмотры

Это счётчик обращений к публичной конфигурации примера с базовой фильтрацией ботов, не доказательство, что конкретная компания просмотрела страницу. Он не определяет уникального человека и может учитывать повторные открытия. Проверки с `?own=1` и открытия политики не учитываются. Любой посетитель может отключить учёт `own=1`; метрика ориентировочная.

Удаление карточки отключает загрузку её примера: посетитель увидит «Пример недоступен». Это сообщение в интерфейсе, **не HTTP 404**: путь `/p/*` обслуживается статическим шаблоном. Удаление не отзывает уже сделанные скриншоты или копии данных.

## 3. Проверка с вашей стороны — приложение продаж

Проводите на тестовой компании, не на реальных клиентах.

- [ ] Вход: неверный пароль не пускает; правильный открывает CRM. После выхода и перезагрузки снова нужен вход. После 10 попыток за 15 минут с IP срабатывает ограничение (не проверяйте это на основной сессии без необходимости).
- [ ] Создайте «Тест Клининг», город Казань, тестовые контакты, зелёный цвет, тарифы 70 / 130 / 170, минимум 2500.
- [ ] Сохраните; ссылка вида `/p/...` открывается в приватном окне, **без входа Vercel и без входа CRM**.
- [ ] Название, логотип, цвет, контакты и цены на примере соответствуют карточке. Измените город/название, сохраните и обновите публичную страницу: данные должны измениться.
- [ ] На ширине телефона нет горизонтального прокручивания; поля и кнопки доступны. Проверьте iPhone/Android, если ваши клиенты ими пользуются.
- [ ] Калькулятор: 50 м² × 70 = 3500 ₽. 80 м² × 130 + окна 1200 = 11600 ₽. При 20 м² поддерживающая — минимум 2500 ₽.
- [ ] Форма: без имени, нормального телефона и согласия не отправляется. С корректными тестовыми значениями показывает **«Тест пройден»** и не скрывает подтверждение.
- [ ] Тестовая форма не требует Telegram, реальные имя и телефон не появляются в Redis и не уходят менеджерам; в CRM увеличивается число тестов формы.
- [ ] Создайте свой текст оффера. Поменяйте поле карточки и сохраните: текст не должен неожиданно замениться стандартным шаблоном.
- [ ] Кнопки WhatsApp, Telegram, MAX открывают **ваши проверенные тестовые чаты**. Убедитесь, что текст, имя и ссылка верны. Сообщение отправляйте только себе/согласившемуся получателю.
- [ ] Если браузер блокирует новое окно, разрешите всплывающие окна именно этому сайту. Для буфера обмена нужен HTTPS и разрешение браузера; при отказе скопируйте текст вручную.
- [ ] Открытие чата оставляет статус «Новый». «Подтвердить, что отправлено» переводит его в «Оффер отправлен».
- [ ] Проверьте поиск, фильтр, повторный вход с другого браузера и CSV. Для большой базы проверьте карточку, которая не попала в первую сотню.
- [ ] Удалите тестовую карточку; её публичная ссылка должна показывать «Пример недоступен».

## 4. Передача настоящего сайта клиенту

1. Создайте отдельную копию репозитория и новый Vercel-проект. Не включайте в него вашу CRM-базу.
2. Откройте **`config.js`**. Замените:
   - `brand.*`: бренд, логотип-текст, надпись и подписи на флаконе, цвет;
   - `city`, `site.url`: город и настоящий HTTPS-домен без завершающего слэша;
   - `contacts.*`: проверенные телефон, email, адрес, часы, срок ответа и ссылки;
   - `legal.*`: реальный оператор данных, ИНН/ОГРН, адрес, email для обращений, дата редакции политики;
   - `pricing.*`: три тарифа, минимум и дополнительные услуги;
   - **`site.demo: false`** — только после настройки реального приёма заявок.
3. Пустые необязательные ссылки на мессенджеры можно оставить пустыми. Не оставляйте нулевые телефоны и `example.com` в обязательных данных.
4. Замените `example.com` в `sitemap.xml`. В `robots.txt` добавьте строку `Sitemap: https://ВАШ-ДОМЕН/sitemap.xml`. Favicon при желании замените логотипом. Для органического поиска перепроверьте title/description, canonical, sitemap и предпросмотры ссылок: персонализация метатего�� выполняется JavaScript, не все внешние превью исполняют его.
5. Шаблонные тексты услуг/FAQ в `index.html` согласуйте с компанией. Если условия или фотография не подходят её бизнесу, замените их до публикации. Юридическая политика — шаблон, а не юридическое заключение.
6. В переменных клиентского проекта **не задавайте `ADMIN_PASSWORD`**. `/api/admin` будет выключен, а публичная загрузка `/p/*` отключена. Сам статический экран входа `/admin` может оставаться доступным — закрытые данные он не выдаёт.
7. Подключите **собственный Redis клиента** и Telegram, как описано ниже.
8. Deploy, подключение домена, затем проверка чек-листа реального сайта.

Для основных данных компании достаточно `config.js`, но домен для Telegram, статический sitemap/robots, секреты и юридические тексты требуют отдельной настройки. Копирование данных карточки CRM в клиентский `config.js` пока ручное: автоматического выпуска отдельного клиентского проекта нет.

## 5. Telegram настоящего клиента

1. Создайте бота в @BotFather и получите токен. Не публикуйте его и не присылайте в чат.
2. Добавьте бота в группу менеджеров или откройте личный чат.
3. В Vercel клиентского проекта добавьте:
   - `TELEGRAM_BOT_TOKEN` — токен;
   - `TELEGRAM_WEBHOOK_SECRET` — случайную строку из латинских букв, цифр, `_` и `-`, 32–64 символа;
   - `PUBLIC_SITE_URL` — `https://домен-клиента`, без пути;
   - `DISPLAY_TZ` — например, `Europe/Moscow`;
   - при желании `LEAD_TITLE` — подпись заявки.
4. Redis: `KV_REST_API_URL` + `KV_REST_API_TOKEN` (или пара `UPSTASH_REDIS_REST_*`). Сделайте Redeploy.
5. Зарегистрируйте webhook **POST-запросом**, не секретом в адресной строке. На своём компьютере с Node.js 22+ скопируйте `.env.example` в `.env.setup`, оставьте только `PUBLIC_SITE_URL` и `TELEGRAM_WEBHOOK_SECRET`, впишите значения. Затем из папки проекта:

```sh
node --env-file=.env.setup scripts/setup-telegram.mjs
```

Должен прийти статус 200 и `{ "ok": true, ... }`. Файл `.env.setup` держите только локально; `.gitignore` исключает `.env.*`, кроме безопасного примера. После настройки удалите его или храните в защищённом месте. **Старая инструкция `GET /api/setup?secret=...` больше не действует.**

6. Напишите боту `/id`. Добавьте полученный ID в `TELEGRAM_CHAT_ID` (у группы он может быть отрицательным). Redeploy ещё раз.
7. Отправьте одну реальную тестовую заявку с собственного номера. Проверьте получение в правильной группе.
8. Проверьте кнопки «Взять в работу», «Связались», «Выполнена», «Вернуть в работу», команды `/leads` и `/lead номер`.

При смене домена обновите `site.url`, `PUBLIC_SITE_URL`, sitemap/robots, сделайте Redeploy и снова зарегистрируйте webhook. Изменение webhook выполняйте осознанно: один бот имеет один webhook, поэтому отдельные клиентские сайты должны использовать разных ботов.

## 6. Чек-лист настоящего сайта

- [ ] `node scripts/check-config.mjs` не находит заглушек; режим — реальные заявки. Эта проверка не заменяет просмотр страниц.
- [ ] Форма получает реальную заявку, показывает номер и не прячет подтверждение.
- [ ] В Telegram предварительная цена соответствует калькулятору, даже если подменить `total` в браузере: сервер пересчитывает стоимость сам.
- [ ] Сервер отклоняет запрос без `consent: true`, неверный телефон, неизвестную услугу/допуслугу, площадь вне 20–250 м² и прошедшую/некорректную дату.
- [ ] Redis сохраняет заявку и факт согласия. При подключённом Redis более 5 запросов с IP за 10 минут ограничиваются (429).
- [ ] Правильные телефонные и социальные ссылки на мобильном устройстве; форма, политика, неизвестный URL (404), логотип, favicon.
- [ ] `ADMIN_PASSWORD` отсутствует; ваша база потенциальных клиентов не подключена.
- [ ] Данные компании и политика согласованы с владельцем. Определены основания обработки, срок хранения, удаление заявок, доступ менеджеров и резервные копии.

**Персональные данные:** Vercel в конфигурации использует регион Frankfurt, Redis может размещаться вне РФ, а заявки передаются в Telegram. Наличие текста про 152-ФЗ не делает такую схему автоматически соответствующей закону. До сбора реальных данных в РФ согласуйте локализацию, передачи и используемый хостинг с юристом; при необходимости перенесите инфраструктуру. Автоматическая очистка по сроку хранения в этой версии не реализована.

## 7. Локальные проверки

Нужен Node.js 22+. Серверные тесты не требуют установки зависимостей и не обращаются к реальным Redis/Telegram:

```sh
npm test
npm run dev
```

`npm run dev` поднимает локальный стенд `http://127.0.0.1:4173`. Пароль только этого стенда: `local-demo-password`. Redis и Telegram здесь имитируются, данные исчезают после перезапуска. Не используйте этот пароль в Vercel. Проверка `npm run check` намеренно завершается с ошибкой, пока в `config.js` остаются заглушки.

Проверки Chromium выполнены на локальном интеграционном стенде с имитацией Redis/Telegram, на ширинах 390 и 1440 px, с недоступным CDN (проверка WebGL-fallback). Реальные Vercel, Redis, доставка Telegram, мобильные приложения мессенджеров и WebGL через загруженный Three.js требуют отдельной проверки по чек-листам выше. Открытие URL чата не доказывает отправку, доставку или чтение.

## 8. Если что-то не работает

| Симптом | Что проверить |
| --- | --- |
| «Приложение выключено» | `ADMIN_PASSWORD` задан в нужном Vercel-проекте/окружении; выполнен Redeploy |
| Ошибка Redis | Полная пара URL+token, привязка интеграции к проекту, лимиты Upstash, логи Vercel Functions |
| Вход не сохраняется | HTTPS, cookie не блокируются, пароль не изменён; при истечении 8 часов войдите снова |
| «Слишком много попыток» | Подождите 15 минут; это защита от перебора, не нужно многократно перезагружать страницу |
| Пример требует вход Vercel | Deployment Protection; используйте предназначенный для публичного просмотра Production-домен |
| «Пример недоступен» | Карточка сохранена, не удалена, Redis и `ADMIN_PASSWORD` подключены, slug скопирован полностью |
| В Telegram ничего нет | На демо это ожидаемо. На клиентском сайте проверьте `demo:false`, токен, ID чата, webhook, Redis и логи |
| MAX не открывает компанию | Нужна проверенная полная ссылка из MAX, не просто номер телефона |
