# Новая 3D-модель и длинные названия

- Подключён пользовательский cleaning_caddy.glb; для текстовой доставки через GitHub он без потерь перепакован в assets/cleaning-caddy.gltf. Геометрия, UV, нормали, индексы и обе текстуры сверены побайтово (55 accessor).
- Фирменный цвет берётся из brand.accent. Этикетка Spray_Label получает текст из brand.bottleName, а при отсутствии — из brand.name. Название автоматически переносится по словам, очень длинные слова — по символам. Текст не обрезается многоточием.
- В CRM название, текст логотипа и надпись на флаконе поддерживают до 80 символов. Пустая надпись на флаконе в персональном демо означает полное название компании. Старые вручную сохранённые короткие надписи не перезаписываются: очистите это поле, если хотите использовать полное название.
- Шапка растёт по высоте; на узких экранах длинный бренд размещается над кнопками. Главный блок отодвигается на фактическую высоту шапки. Название в подвале тоже переносится.
- Вместо старого CSS-флакона при ошибке библиотеки/модели/WebGL показывается настоящий рендер новой модели с отдельной подписью компании. Встроенный рендер намеренно без чужого бренда.
- Модель не вращается вокруг своей оси при перетаскивании: только небольшой наклон мышью на компьютере. На телефоне нет колебания; системное ограничение анимации и кнопка паузы учитываются.
- Three.js и совместимый GLTFLoader загружаются стандартными CDN script-тегами одной версии (0.147.0). Локальной сборки и npm-зависимостей нет. Для встроенных данных glTF в connect-src добавлена только схема data:.

## Проверено локально

46/46 автоматических тестов. 12 сочетаний ширины 320/390/768/1440 и короткого/длинного/80-символьного слитного названия. Без горизонтальной прокрутки, наложения шапки на главный текст и обрезания имени. Дополнительно: отказ загрузки модели, reduced motion, ручная пауза, потеря WebGL-контекста, тест��вая заявка с локальными имитациями Redis и Telegram. JavaScript-ошибок страницы нет. Статичная мобильная версия проверена визуально после исправления отступов. Библиотеки в браузерном стенде подставлялись из тех же исходных файлов версии r147: доступность CDN из реальной сети и настоящий Vercel-деплой здесь не проверялись.

## Публикация

Ветка feat/caddy-responsive-brand основана на main cb84fee079eadc84590db58fe13eefdb1cf431d1. После проверки объедините её с main и дождитесь Ready в Vercel. Настройки Redis/Telegram менять не нужно. На основном сайте и в /p/<slug> используется одна модель. После публикации проверьте обычную страницу и персональное демо на телефоне; форма должна работать и при блокировке CDN.
